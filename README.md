## Цель

Создать личный сайт, где можно записывать блюда за неделю, видеть калории, рассчитывать калорийность блюда и порции и вести свою книгу рецептов. Интерактивная неделя должна ощущаться как игра: добавленные блюда постепенно заполняют иллюстрированный альбом.

## Структура сайта

| Раздел | Назначение |
|---|---|
| Неделя `/week` | Семь дней, приёмы пищи, дневные и недельный итоги, переключение недель. Два представления: «Стол» и «График». |
| Книга рецептов `/recipes` | Свои рецепты, поиск, фото или иллюстрация, ингредиенты, шаги, выход и ккал на порцию. Из рецепта можно добавить запись в дневник. |
| Калькулятор `/calculator` | Вес ингредиентов и ккал на 100 г, калории всего блюда, порции или съеденного веса. Расчёт можно сохранить как рецепт или запись дневника. |
| Настройки `/settings` | Предложенные функции: часовой пояс, единицы отображения и экспорт данных. |

Основной сценарий: открыть день → выбрать приём пищи → ввести блюдо вручную или выбрать рецепт → указать количество → сохранить. Карточка появляется на столе, а дневной и недельный итоги обновляются. Нажатие на карточку открывает запись для изменения или удаления. День без записей явно помечается на графике. Игровой прогресс отражает записи в альбоме.

## Архитектура и расчёты

Предложение для первой версии: одно приватное веб-приложение на TypeScript с серверной частью и PostgreSQL. Модули: дневник, рецепты и расчёты. При хранении пользовательских фото использовать приватное файловое хранилище. Неделя по умолчанию с понедельника по воскресенье.

| Сущность | Основные данные |
|---|---|
| `User` | Аккаунт и часовой пояс |
| `Ingredient` | Название, состояние продукта, ккал на 100 г, источник |
| `Recipe` | Название, шаги, фото, число порций, вес готового блюда при наличии |
| `RecipeIngredient` | Ссылка на ингредиент, вес, использованное значение ккал на 100 г |
| `DiaryEntry` | Владелец, локальная дата, приём пищи, опциональная ссылка на рецепт, сохранённое название, количество и единица, калорийность на единицу и итог, признак приблизительной оценки |

- Калории ингредиента = граммы × ккал на 100 г ÷ 100. Калории блюда = сумма по ингредиентам.
- Калории порции = калории блюда ÷ число порций. Допускаются дробные порции при записи съеденного.
- При известном весе готового блюда калории съеденного количества = калории блюда × съеденный вес ÷ вес готового блюда.
- Вес и калорийность ингредиента относятся к одному состоянию продукта. Для ручного ввода можно указать ккал напрямую и пометить оценку как приблизительную.
- Запись хранит калории и данные для пересчёта количества. После изменения рецепта прошлые записи используют сохранённые значения. Все недельные представления получают итоги из записей дневника.

## Текущий этап

Версия 1 опубликована в Sites с публичным доступом: [Кулинарный дневник](https://culinary-diary-week.coralnacre7.chatgpt.site). Проект Sites: `appgprj_6b06afdcb41481918c5fdaeafc68546e`. Данные каждого пользователя хранятся в его браузере отдельно для этого адреса.

Первый этап реализован в [index.html](index.html). Открой файл в Edge или Chrome. Доступны переключение дней и недель, ручная запись блюда, изменение, удаление с отменой, дневные и недельные итоги. Пустое и заполненное состояния можно посмотреть, добавив блюдо. Проверка в Edge охватила сохранение, пересчёт итогов, изменение, переход между неделями, удаление и восстановление.

Для прототипа выбраны один HTML-файл без зависимостей и локальное хранилище браузера. Записи привязаны к браузеру и адресу файла. Серверная архитектура и PostgreSQL остаются предложением для следующей версии. Рабочая палитра первого экрана: бумажный фон, сливовый текст, томатный акцент и лавандовый фон выбранного дня.

Книга рецептов добавлена в тот же HTML-файл. Можно создать и изменить рецепт, найти его по названию, указать ингредиенты, шаги, выход и число порций. Редактор рассчитывает калории всего блюда и порции. Дробную порцию можно записать на выбранную дату и приём пищи. Запись хранит название, количество, исходную калорийность порции и итог, поэтому изменение рецепта сохраняет историю дневника. Рецепты хранятся под ключом `culinary-diary.recipes.v1`, записи дневника по-прежнему под `culinary-diary.entries.v1`. В Edge проверены ручная запись, создание и поиск рецепта, расчёт дробной порции, запись на выбранную дату и сохранение исторической калорийности после правки рецепта.

Калькулятор доступен из основной навигации. Он показывает калории всего блюда, одной порции и на 100 г при известном весе готового блюда. Разовый расчёт можно записать в дневник без создания рецепта или сохранить в книгу. При записи выбираются дата, приём пищи и количество порций или граммов. Дробные значения принимают запятую и точку. Edge подтвердил запись 1,5 порции и 300 г, пересчёт дневного итога, сохранение рецепта и совместимость с прежним сценарием книги.

В разделе «Неделя» доступны «Стол», «График» и «Альбом». График открывает выбранный день, альбом группирует блюда по датам и показывает число дней с записями. Карточки открывают редактор. При добавлении или редактировании записи, рецепта либо расчёта можно выбрать фото JPG, PNG или WebP до 25 МБ. Браузер уменьшает изображение до 800 пикселей по длинной стороне и хранит вместе с данными. При записи порции фото рецепта копируется в дневник. Количество фото ограничено доступным хранилищем браузера.

Для локального запуска открыть `start-local.cmd` и перейти на http://127.0.0.1:8767/. Сервер использует Node.js и слушает только локальный адрес. Хранилища по адресу файла и по HTTP раздельные. Сервер вернул HTTP 200 при проверке из собственного процесса, встроенный браузер не смог подключиться через окружение Codex. В отдельных проверках Edge прошли фото в дневнике и рецепте, альбом, график, калькулятор и запись порций.

Критерий готовности первой версии: можно записать блюда за неделю, сохранить рецепт, добавить дробную порцию и открыть прошлую неделю с корректными итогами после изменения рецепта.
